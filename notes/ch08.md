## 尋找最佳training config

### Fit training steps in Memory
**GPU夠：各種平行技術**
**GPU不夠：**
- full activation recomputation
- gradient accumulation 
> gradient checkpointing是activation recomputation的一種，但是會保留中間一些act結果，full則是全部重算

> grad accu是算好幾次（每次一組micro batch的） gradient → 加在一起 → 最後才更新一次模型。
### 調整至 target global batch size
**to increase GBS:**
- 擴大DP規模/增加gradient accumulation步數 （$global\ batch\ size = micro\ batch\ size*steps$）
- (for long context)上下文平行（CP）
**to decrease GBS:**
- 縮減DP，改用其他平行策略
- (for long context)降低CP程度

### 最佳化training throughput
- 擴大張量平行（利用節點內的高速頻寬），直到平行度接近節點大小，以便減少其他平行化的需求
- 在維持目標批次大小的前提下，增加使用 ZeRO-3 的資料平行
- 當資料平行的通訊開始成為瓶頸時，轉而使用管線平行
- 平衡各種參數（mbs/GBS/etc）和平行化策略

### Benchmark config
- 隨著節點數增加（更高的平行度），我們觀察到效率下降。這個效應在較小的模型上特別明顯，因為它們的計算量對模型大小的比值較低
- 隨著模型大小增加，記憶體需求大幅成長。在節點較少時，這會造成兩種情況：模型完全放不下，或者勉強放得下、卻因為運作在接近 GPU 記憶體上限的狀態而效率低落
- 效能高度取決於實作品質(程式碼的優化)
